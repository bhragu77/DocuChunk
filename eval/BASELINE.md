# Retrieval Baseline — Dense-Only (the "before" for Phase 8)

Generated by `python -m app.eval.harness` with the **real** local
`sentence-transformers/all-MiniLM-L6-v2` model. Machine-readable copy:
[`baseline_dense_only.json`](./baseline_dense_only.json). The Phase 8 result
(hybrid + rerank) is measured against this in
[`phase8_comparison.md`](./phase8_comparison.md).

- **Fixture:** `tests/fixtures/eval_set.json` — a **hardened** set of 7 self-authored
  synthetic documents with deliberate **near-miss distractors**: two tech companies
  with similar financials (Apple Inc. vs Pear Computing Inc.), two fruit-growing guides
  with per-acre economics (apple orchard vs citrus grove), and three device manuals
  whose identifiers are transposed decoys of each other (part `88-AZ-0097` vs
  `88-AZ-0079`, error `E-4521` vs `E-4251`, firmware `4.0.2` vs `4.2.0`). 25 queries,
  graded by text (each query's `expected_snippets` resolve to the real deterministic
  chunk_ids that actually landed in the store).
- **Queries** are user-style paraphrases that avoid mirroring the answer chunk's
  distinctive tokens, plus bare exact-code queries (`88-AZ-0097`, `E-4521`, `IP67`,
  `1-800-555-0142`). This is deliberately harder than a query set that echoes the
  source — a set where dense-only already scores ~1.0 proves nothing.
- **Retrieval:** dense only — `embed_query` → `collection.query(top_k=5)`, cosine.
- **Provider:** real neural dense (`semantic: true`). **k = 5.**

## Results (real MiniLM, k=5)

| metric | all | ambiguous_entity * | identifier * | general |
|--------|:---:|:------------------:|:------------:|:-------:|
| recall@5    | **0.960** | 1.000 | **0.909** | 1.000 |
| MRR         | **0.920** | 1.000 | **0.864** | 0.929 |
| precision@5 | **0.240** | 0.200 | 0.291 | 0.200 |

`*` = category flagged as a case Phase 8 (BM25 + rerank) targets.

## Where dense-only breaks (this is the point of the hardened set)

Unlike the earlier trivial set (where dense-only already scored MRR ~0.92 with the
correct chunk almost always at rank 1 and nothing to discriminate), this set forces
real failures:

| query | category | dense rank | why |
|-------|----------|:----------:|-----|
| `q-gx4200-part-bare` (`88-AZ-0097`) | identifier | **MISS (not in top-5)** | a bare alphanumeric part number carries no semantic anchor; MiniLM blurs it against the decoy `88-AZ-0079`. |
| `q-support-phone-bare` (`1-800-555-0142`) | identifier | 2 | bare phone number, same reason. |
| `q-orchard-varieties` | general | 2 | citrus "varieties fetch the strongest prices" is a semantic near-miss for the apple varieties chunk. |

recall@5 is **0.960**, not 1.0 — dense-only genuinely loses a query. Identifier
recall is **0.909**. These are the gaps Phase 8 must close.

## What Phase 8 does to these (see phase8_comparison.md)

- **Hybrid (dense + BM25 via RRF)** recovers the bare part number (MISS → rank 1) and
  the phone number (2 → 1); flagged-category MRR **0.917 → 1.000**, recall → 1.000.
- **But hybrid is not free:** BM25 injects a lexical distractor that *regresses* two
  semantic `general` queries (`q-orchard-varieties`, `q-orange-varieties`). The
  **cross-encoder rerank recovers both**, and lifts aggregate MRR to **0.980**.
- **Where dense already held up** — the near-miss *error codes* (`E-4521` vs `E-4251`)
  and model-anchored natural-language identifier queries — all three methods score
  rank 1. MiniLM's subword tokenization distinguishes those, so hybrid's win is
  concentrated on **bare** identifiers, not all of them. That is the honest result.
